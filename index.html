No.02节点与路由ROUTE & NODES

节点分布描述的是服务接入点的物理与逻辑位置,路由描述的是数据在多段链路之间被中转、转发或直连的方式。理解这两件事,才知道为什么同样的客户端在不同档位下表现不同。

OUTBOUND PATH

典型出口路径示例

本机客户端⇢本地区接入节点⇢中转骨干(公开/专线)⇢境外落地

同一段链路中,中转骨干的等级与带宽分配决定了晚高峰的稳定性,这也是不同档位之间最主要的差别来源。

问:节点到底分几类?

对外服务节点通常按用途分成三组。第一组是"入口节点",负责接收客户端的加密连接,部署在境内或近端的机房。第二组是"中转节点",负责把入口收到的数据送往境外落地点,常见的区分是普通 BGP 中转与 IPLC 专线中转。第三组是"落地节点",提供最终对外网络的 IP 与地理位置,决定解锁流媒体与跨区域服务的实际表现。

TYPE · A
普通线路节点池

基于公开 BGP 中转的入口与落地组合,带宽充足、延迟适中,适合日常浏览与基础解锁,通常作为入门档位的承载资源。

TYPE · B
IPLC 专线节点

专线资源在晚高峰保留独立带宽,与公开链路分离排队,适合游戏、远控等对抖动敏感的会话,通常作为旗舰档位的核心权益。

问:路由策略如何影响体验?

路由策略描述的是数据从入口到落地经过哪几段、是否走专线、是否按目标地区优选。一般而言,绕行越少、跳数越短、骨干等级越高,速度与稳定性越好。游戏与远控这类对丢包敏感的业务,通常更需要"专线 + 短路径"的组合,而非单一追求节点数量。

页面声明

本页未对节点总数、上线地区、晚高峰带宽、丢包率等指标给出数字承诺,具体线路等级与所属类型以订阅后客户端下发的实际配置为准;部分中转骨干为公开资源,服务等级随上游变化。

问:订阅完成后,接入需要几步?

从订阅成功到可以正常转发流量,通常包含三步:获取订阅链接、在客户端粘贴并同步节点、把系统或浏览器的代理指向本地端口。具体步骤如下:

  1. 登录订阅后台,复制本档位对应的订阅地址,确认未包含多余空格。
  2. 在客户端"订阅"或"配置"页粘贴地址,触发一次同步,让节点列表更新到本地。
  3. 选择节点与路由模式,启动系统代理或浏览器代理,确认本地端口与客户端一致。
  4. 在浏览器或应用中访问任意公开站点,验证连通后再使用具体业务,避免一上来便压测专线资源。

No.05常见疑问FAQ

以下为订阅前最常被问到的若干问题,按编号阅读即可,问题清单按主题归并,而非按出现顺序排列。

Q01三档之间,真正决定体验差别的是流量大小,还是节点等级?+

流量大小决定"可用多久",节点等级与路由策略决定"用起来如何"。基础版对应入门级链路,适合浏览与基础流媒体;旗舰版引入 IPLC 专线与全节点原生解锁,适合对抖动感知的场景;团队版则把高带宽资源与多设备能力作为主轴,适合小团队内并行使用。

因此,在流量还没耗尽之前,节点等级往往是体验分水岭;流量告罄之后,补量与升级两件事都需要重新评估。

Q02页面里出现的"原生流媒体解锁"具体指什么?+

"原生解锁"指的是落地节点所提供的 IP,本身被目标流媒体平台视为该地区的本地访问,无需借助额外的转发或中转伪装。它影响的是"能不能打开"的层面,而非"打开后有多流畅"。流畅度仍取决于中转链路的等级与晚高峰排队。

具体覆盖范围与维护节奏以订阅后客户端内"解锁状态"页提示为准,本页不预先列出具体平台清单。

Q03同时在线设备数是怎么计算的?路由器算一台吗?+

"同时在线设备数"按客户端与订阅链接的活跃连接计数。当客户端被路由器固件调用时,路由器本身计为 1 台,而局域网内通过它上网的设备不再单独计费;反之,如果局域网内每台设备各自运行客户端,则按并发连接数累加。

团队版 20 台的设定即考虑到了多设备的并行场景,允许在办公环境下将路由器作为统一出口。

Q04IPLC 专线与普通中转的差别,在哪些场景才比较明显?+

在浏览与点播场景下,两者差异主要表现在高峰时段的稳定性;但在游戏、远控、视频通话等对丢包和抖动敏感的场景下,IPLC 专线因不与公开链路一起排队,体验差别会被显著放大。

若日常使用以浏览为主,普通线路已足够;若需要长时间的稳定会话,建议升级到含 IPLC 资源的档位。

Q05计费是从订阅日还是固定日期开始?+

按月与按年两种付款均以结算成功的时间点为起点,而非自然月的 1 号。流量额度按订阅周期计算,在周期结束或主动取消前不会清零转入下一周期。

续费策略、暂停与退款条款以《服务协议》为准,本页仅整理订阅前需要前置了解的事项。

Q06如果我对网络协议不熟悉,哪一种客户端最省心?+

桌面与移动客户端通常提供一键同步与可视化节点选择,适合不熟悉协议的用户;路由器固件适合设备数量较多、希望一次配置长期受益的家庭或办公环境,但需要在后台网页中完成初次设置。

无论选择哪种客户端,首次接入后建议先访问公开站点做连通验证,再用于具体业务。
